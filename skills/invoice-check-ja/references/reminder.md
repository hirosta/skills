# 催促の下書きの決まり

期日を過ぎた請求を並べ、利用者が渡した支払いの履歴で初期案の強さを変える。履歴なし・いつも期日どおりは①、ときどき遅れるは②、何度も遅れるは③を候補とする。これは下書きの選び方であり、自動的に段階を上げたり送信したりしない。③の次の対応が未指定なら確認を待ち、必要なら①の確認案だけを返す。

催促前に請求書番号、未入金額、期日、基準日時点の入金状況を確認する。一部入金では未入金額と元の請求総額を区別する。件名には請求書番号・今回お願いする金額・元の支払期日を入れる。冒頭3行で用件と必要な行動が分かるようにする。まず件名と冒頭3行を利用者に示し、確認後に本文を展開する。

以下の角括弧は利用者が確認した情報だけで置き換える。返信期限は支払期日とは別であり、勝手に設定しない。すべての型に行き違いのお詫びを入れる。

## ① ご確認のお願い

件名：ご入金状況のご確認：請求書［番号］／［未入金額］円／支払期日［日付］

冒頭3行：

```text
［宛先］御中
請求書［番号］（［未入金額］円、支払期日［日付］）について、ご入金状況を確認させてください。
行き違いですでにお支払い済みでしたら、失礼いたしました。
```

本文の続き：お手数ですが、お手続きの状況をお知らせいただけますでしょうか。請求内容に不明点がありましたら、あわせてお知らせください。［差出人］

## ② お支払いのお願い

件名：お支払いのお願い：請求書［番号］／［未入金額］円／支払期日［日付］

冒頭3行：

```text
［宛先］御中
支払期日［日付］の請求書［番号］につき、［基準日］時点で［未入金額］円のご入金を確認できておりません。
お支払いの予定日をお知らせいただけますでしょうか。
```

本文の続き：行き違いですでにお支払い済みでしたら、失礼いたしました。請求内容の確認が必要な場合はお知らせください。［差出人］

振込先を付ける場合は利用者から受け取った内容だけを載せる。未提供なら省略し、別の案内が必要かを利用者に確認する。口座情報を過去の推測や架空の例から埋めない。

## ③ 最終のご連絡

件名：最終のご連絡：請求書［番号］／［未入金額］円／支払期日［日付］

冒頭3行：

```text
［宛先］御中
支払期日［日付］の請求書［番号］について、［基準日］時点で［未入金額］円が未入金となっております。
お支払いの予定を［利用者が決めた返信期限］までにお知らせください。
```

本文の続き：［利用者が決めた次の対応］。行き違いですでにお支払い済みでしたら、失礼いたしました。ご事情や請求内容について確認が必要な場合はお知らせください。［差出人］

次の対応や期限が未確認なら「要確認」のままにし、完成稿としない。法的手続き、取引停止、損害金をこちらから書き足さない。法的な手続きをほのめかす文は利用者の明示指示があるときだけ検討し、必要なら税理士・担当部署・法律の専門家に確認する。遅延損害金の計算は扱わない。

## 架空の例と失敗の見直し

[修正前](../examples/reminder-before.txt)と[件名・冒頭3行の提示案と修正後](../examples/reminder-after.md)は、invoice-01.csvの架空の請求が材料。これは検証用の比較で、利用者が承認した送信用の文面ではない。

| よくある失敗 | 適用する決まり | 修正後 |
| --- | --- | --- |
| 「至急」とだけ書いて対象を特定できない | 件名に番号・金額・期日 | 架空-01、1,100円、2026-10-30を件名へ |
| 履歴を見ず強く責める | いつも期日どおりなら① | 入金の確認をお願いする形へ |
| 翌日までの支払いを勝手に求める | 期限を作らない | 支払い状況の確認依頼へ |
| 法的手続きをほのめかす | 明示指示がある場合だけ | 該当文を削除 |
| 入金済みの可能性を無視する | 行き違いのお詫び | 冒頭3行へ追加 |
| 振込先を補作する | 利用者が渡した情報だけ | 振込先を載せず、必要なら確認 |

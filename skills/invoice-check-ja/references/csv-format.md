# 入力CSVの仕様

UTF-8（BOM可）、カンマ区切り。1枚または複数枚を1ファイルにまとめられる。列の順序は任意だが、下の列名はすべて1回ずつ必要。不要な値は空欄とし、空欄の代わりに0を入れない。行種別と異なる列の値、未知の列名、重複列名、列数違いは入力エラーになる。各請求書には `header` がちょうど1行必要。行順は問わない。

```csv
kind,invoice_id,issuer,registration,recipient,issue_date,due_date,basis,rounding,closing_day,payment_months,payment_day,weekend,invoice_amount,paid_amount,history,transaction_date,description,rate,reduced,amount,tax
```

| 行種別 | 値を入れられる列 | 意味 |
| --- | --- | --- |
| 全行 | kind, invoice_id | kindはheader・line・total。invoice_idは同じ請求書を結ぶ必須キー兼請求書番号。番号が未確認なら仮のキーと明記し、催促へ転記しない |
| header | issuer, registration, recipient | 発行者名、登録番号、受取者名 |
| header | issue_date, due_date | 請求日、原文に記載された支払期日 |
| header | basis, rounding | 税抜・税込、切り捨て・切り上げ・四捨五入。どちらも請求書全体で統一 |
| header | closing_day | 締め日。末または1〜31 |
| header | payment_months, payment_day | 締め月から0・1・2か月後、末または1〜31。翌月末は1と末、翌々月10日は2と10 |
| header | weekend | 休日なら前の営業日は前、次の営業日は次。土日と提供された休日を連続して避ける |
| header | invoice_amount, paid_amount | 原文の請求総額と基準日時点の入金額。入金なしを確認したときだけ0を入れる。一部入金は実額 |
| header | history | いつも期日どおり・ときどき遅れる・何度も遅れる。未提供は空欄 |
| line | transaction_date, description | その明細の取引日と内容。期間表示はこのCSVでは扱わず、日付へ変換できなければ手読みで補う |
| line | rate, reduced, amount, tax | 税率10・8、軽減対象の表示はい・いいえ、明細の対価、原文にあれば明細税額。taxは任意 |
| total | rate, amount, tax | 税率別の適用税率、対価合計、消費税額等。明細から補作せず原文の値を転記 |

金額は非負、整数部15桁以内、小数2桁以内の半角数字。通貨記号・桁区切り・指数表記は不可。ゼロは記載ありとして扱う。明細のamountは数量×単価ではなく、値引き等を反映した明細の対価。負の金額、返還・相殺・税率混在の値引きは扱わない。税額の検算は1円単位で行う。金額・税率の適用自体が正しいかは別途人が確かめる。

日付は `2026-09-30` または `令和8年9月30日`・`平成31年4月30日`。元年可。直後に `（水）` または `(水)` の曜日を付けられる。存在しない日付・改元日の範囲外・未対応の書式は終了値2。日付の空欄は検出結果として表示する。基準日は `--as-of` で必須指定し、今日を自動採用しない。

休日一覧はUTF-8、1行1日付（同じ書式）、空行可。空ファイルは「この計算範囲に休日なし」と利用者が確認した一覧を意味する。渡さない場合は祝日を考慮せず注意を表示する。一覧の完全性は検証しない。

締め日は各取引日を含む最初の締め日とする。20日締めでは21日の取引は翌月20日締め。存在しない日（2月の31日など）はその月の末日に寄せる。これは本スキルの計算上の約束であり、契約に合うか確認する。複数の締め期間を含む請求書、支払条件の不足、計算期日と記載期日の不一致では期日を確定せず、超過一覧から外す。未確定でも超過していないという意味ではない。

未入金額はinvoice_amount−paid_amountで求める。期日が確定し、基準日が期日より後であるものを一覧に出す。入金情報不足は催促保留として表示し、完済・過入金は一覧から外す。点検の指摘が残る請求を、そのまま送信可能とは扱わない。

貼り付けた文面は利用者とこの形式へ対応させてから使う。振込先はスクリプトでは扱わず、必要なときだけ利用者から文案用に受け取る。個人番号を収集しない。出力には請求書番号や金額が含まれるため、共有前に利用者が公開範囲を確認する。

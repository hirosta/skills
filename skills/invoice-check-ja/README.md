# invoice-check-ja

日本の通常の請求書を送る前に、インボイスの記載事項、税額、日付、支払期日を点検するスキルです。期日を過ぎた請求があれば、取引先の支払いの履歴に合わせて催促の文面を下書きします。会計サービス・メールには接続せず、送信・予約・外部照会はしません。

## 点検すること

| 項目 | 機械点検と人の確認 |
| --- | --- |
| 適格請求書の6項目 | 発行者・登録番号、取引年月日、取引内容・軽減対象表示、率別対価合計・適用税率、率別消費税額等、受取者。空欄を表示し、原文との対応は人が読む |
| 登録番号 | Tと13桁の数字、法人番号のチェックデジット。実在・登録状況は照会せず利用者が公表サイトで確認 |
| 税額 | 10%・8%、税抜・税込に対応。率ごとに合計して1回だけ端数処理。明細税額がすべてあれば合計との差も表示 |
| 日付 | 平成・令和を西暦へ換算し、表記混在、付記された曜日の不一致、取引日より前の請求日を表示 |
| 支払期日 | 月末・20日等の締め日、当月・翌月・翌々月の支払日から計算。土日の前・次の扱いを必須指定し、祝日は利用者の一覧だけを使う |
| 催促候補 | 基準日で期日を過ぎた請求と未入金額を表示。完済・期日当日・期日未確定分は対象外。入金状況不明は保留 |

根拠と理由は [invoice-rules.md](references/invoice-rules.md)、入力の詳細は [csv-format.md](references/csv-format.md)、催促の3段階と失敗例は [reminder.md](references/reminder.md) を参照してください。

## 入れ方

スキルを読み込めるAIエージェントのスキル用フォルダーへ `skills/invoice-check-ja/` をフォルダーごとコピーします。`LICENSE` も含めてください。同名のフォルダーがある場合は内容を確認し、上書きするか決めてからコピーします。他のスキルは必須ではありません。

補助スクリプトにはPython 3.9以上を使います。標準ライブラリだけで動き、追加依存は不要です。

## 使い方

```text
invoice-check-jaで、この架空の請求書を送る前に点検してください。
端数処理は切り捨て、月末締め翌月末払い、休日は前の営業日です。
基準日は2026-10-31、入金額は0円と確認済みです。
履歴はいつも期日どおりです。祝日一覧は別途渡します。
期日を過ぎていたら、まず催促案の件名と冒頭3行を見せてください。
```

入力は貼り付けた内容か独自CSVです。足りない材料だけを確認し、推測で埋めず「要確認」にします。貼り付けはCSVへの対応を確認してから機械点検します。ファイルの作成・変更が必要なら、内容と保存先を利用者が確認してから行います。文案は会話内に返します。

リポジトリのルートから架空の例を実行する場合：

```bash
python3 skills/invoice-check-ja/scripts/check_invoice.py skills/invoice-check-ja/examples/invoice-01.csv --as-of 2026-10-31 --holidays skills/invoice-check-ja/examples/holidays.txt
```

`--as-of` は必須。`--holidays` を省略すると、祝日を考慮していない旨を表示します。休日一覧はUTF-8の1行1日付です。同梱の `holidays.txt` は休日処理を説明するための**架空の休日**1日で、実際の祝日一覧ではありません。

CSVはheader（見出し）・line（明細）・total（率別合計）の行をinvoice_idで結びます。全列と選択肢は [CSV仕様](references/csv-format.md) に定義しています。明細から原文の率別合計を補作すると欠落を検出できなくなるため、記載がなければ空欄またはtotal行なしのまま渡してください。

スクリプトは指定ファイルの読み取りと標準出力のみで、入力・設定の変更、ネットワーク接続は行いません。検出があっても終了値0、引数・入力形式の誤りは2。エラーも標準出力へ返します。出力には番号や金額が含まれるので共有先を確認してください。

## 架空の素材について

会社名・取引・金額・番号・休日はすべてこの検証用に作った架空のものです。実際の請求や送金には使えません。実在の人物・口座は含めていません。

- invoice-01・10の登録番号 `T9000000000000` は、基礎番号の12桁がすべてゼロという明らかに架空の教材用番号です。先頭9は算式に一致するため、この2枚では番号の形式点検も通ります。実在・登録を示すものではありません。
- invoice-02の `T000` は桁数の誤りを検出するためのものです。
- その他の `T0000000000000` は形式だけを満たし、法人番号のチェックデジットは不一致です。このため「要確認」を出すことが期待結果です。個人事業者の登録番号の実例としては使っていません。

## 試した結果

条件：GPT-6（Codex）が同梱の架空CSV10枚を作成し、同じモデルがスクリプトを実行して出力を照合しました。基準日は2026-10-31、休日一覧は同梱の架空の1日を指定しました。実際の請求書や公表番号への照会はしていません。自動テスト・テストスイートは作成していません。

「仕込んだ確認点」は、番号の共通の要確認を除いて各素材に意図的に入れた欠落・不一致・材料不足です。同じ原因から出る税額不一致と明細合計差は別の表示として数えます。

| CSV | 仕込んだ確認点 | 確認点の検出 | 出力の直すべき点 / 要確認 | 基準日の超過一覧 |
| --- | --- | --- | --- | --- |
| [01](examples/invoice-01.csv) | 問題なしの税抜10% | 追加指摘0 | 0 / 0 | 1件、1日超過、1,100円 |
| [02](examples/invoice-02.csv) | 登録番号の桁数 | 1 / 1 | 1 / 0 | 1件 |
| [03](examples/invoice-03.csv) | 明細ごとの端数処理：記載税額2円と一括3円、明細税額合計との差−1円 | 2 / 2 | 1 / 2 | 1件、金額の確認が必要 |
| [04](examples/invoice-04.csv) | 和暦・西暦の混在 | 1 / 1 | 0 / 2 | 1件 |
| [05](examples/invoice-05.csv) | 税率別合計の欠落 | 1 / 1 | 1 / 1 | 1件 |
| [06](examples/invoice-06.csv) | 受取者名の欠落 | 1 / 1 | 1 / 1 | 1件 |
| [07](examples/invoice-07.csv) | 9月30日（水）を月曜と表記 | 1 / 1 | 1 / 1 | 1件 |
| [08](examples/invoice-08.csv) | 取引日より前の請求日 | 1 / 1 | 1 / 1 | 1件 |
| [09](examples/invoice-09.csv) | 取引内容・軽減表示の欠落、端数処理・休日の扱い・入金額・履歴の未指定 | 6 / 6 | 2 / 5 | 0件、期日未確定で保留 |
| [10](examples/invoice-10.csv) | 問題なしの税込10%・8%、和暦、20日締め翌々月10日払い、完済 | 追加指摘0 | 0 / 0 | 0件 |

意図的に入れた確認点は14件中14件の表示を確認しました。03〜09ではこれに加えて架空番号のチェックデジットの要確認が各1件出ています。問題なしの01・10では「直すべき点」「要確認」とも0件で、今回の素材に余分な指摘はありませんでした。これはこの素材と実装の照合であり、一般の請求書に対する精度の評価ではありません。

10枚すべてで終了値0でした。<一時領域>の追加の架空素材でも、切り上げ・四捨五入、うるう年の月末、20日を過ぎた取引の翌締め、土日と提供休日の連続した繰下げ、一部入金・完済・入金額不明、記載期日と計算期日の不一致、記載事項の複数欠落を手動確認しました。期日当日は一覧に入らず、祝日一覧なしでは注意を表示しました。

不正な日付・元号の境界、NaN、未対応税率、不正な文字コード、空CSV、引数不足は終了値2、ヘルプは0を確認しました。構文・ASTと字下げを確認し、インポートが標準ライブラリだけであること、作業対象のコードを実行していることを確認しました。ruffは未導入のため未実行です。スキル共通検証ツールは必要な追加依存がなく実行できなかったため、frontmatter・命名・リンクを直接点検しました。追加依存は導入していません。

## 催促の修正前と修正後

[修正前](examples/reminder-before.txt)と[提示案・修正後](examples/reminder-after.md)を同じ架空の材料から作り、同じモデルで比較しました。利用者に提示して承認を受ける対話の往復、実際の送信は未実施です。

| 決まり | 修正前 | 修正後 |
| --- | --- | --- |
| 履歴で段階を選ぶ | 履歴を無視した強い要求 | いつも期日どおりなので①の確認依頼 |
| 件名に番号・金額・期日 | 「至急のお支払いについて」 | 架空-01、1,100円、2026-10-30を明記 |
| 勝手な期限を作らない | 明日までに必ずと要求 | 手続きの状況を尋ねる |
| 法的な手続きは明示指示があるときだけ | 手続きをほのめかす | 該当文を削除 |
| 行き違いのお詫び | なし | 冒頭3行に記載 |
| 提示の順序 | いきなり本文 | 件名・冒頭3行の提示案と本文を分けた |

振込先が未提供なので、修正後には載せていません。3段階の型、次の対応が未定の③の保留、よくある失敗は [reminder.md](references/reminder.md) にまとめています。

## 分かっていないこと・範囲外

- 実際の請求書の様式の多様さ、複数書類や期間表示、会計サービスから書き出したCSVの形との違いは未検証です。独自CSVへの対応と原文の照合が必要です。OCR・PDFからの抽出はしません。
- 個人事業者の登録番号に法人番号のチェックデジットを適用できるかは確認していません。不一致を誤りと断定せず、人が公表サイトを確認します。一致でも登録の証明にはなりません。
- 祝日一覧の正確性・完全性、契約の例外、取引内容からの税率判定は人の確認が必要です。対応は10%・8%に限り、他の税率や制度改正への自動追随はしません。
- 通常の適格請求書の非負の金額だけが対象です。簡易インボイス・返還インボイス、源泉徴収、2割特例などの税額計算の特例、遅延損害金、非課税・免税・旧税率、外貨、負の明細・相殺、異なる締め期間の一括請求は範囲外です。
- 税務・法律の判断、仕入税額控除の可否、督促の法的な効果は判断しません。必要なら税理士・担当部署へ確認してください。
- 催促文の関係性への適合、利用者の確認応答を含む対話、入金までの実運用は未検証です。作業時間・入金速度・品質の改善は測定しておらず、効果を保証しません。

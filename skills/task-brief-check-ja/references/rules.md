# 点検の決まりと理由

| 項目 | 点検することと理由 |
| --- | --- |
| 目的 | 何のための作業で、終わると何が良くなるかを1〜2文で読めるか。目的が分かれば、複数の進め方から仕事に合うものを選べる。 |
| 範囲 | やること、やらないこと、対象のファイル・ページ・データが特定できるか。変更してよい場所と参照だけの場所を区別すると、別の作業に踏み込まずに済む。 |
| 受け入れ条件 | 「きれいにする」を「一覧に合計列が表示される」「出力と元データの件数が一致する」のように、成果物を見て判定できる条件にする。確認方法や比較先が必要なら明記する。 |
| 前提の数値・日付・名前 | 件数、単位、対象期間、期限、基準日、対象名に必要な値が本文にあるか。「前に話した」「いつもの」「例の」「さっきの」が何を指すか尋ねる。値が明記されていれば読み手が記憶に頼らず作業できる。 |
| あいまいな言葉 | 「いい感じに」「適宜」「よしなに」「など」「なるべく」「できれば」が作業の範囲や優先順位を変えるなら示す。「何を含めますか」「必須ですか」のように問いにする。例示や裁量の意図が明確な表現は文脈で判断する。 |
| 取り消しにくい操作 | メール・メッセージの送信、公開、本番反映、削除、支払い、外部サービスへの登録ごとに、AIができる操作と、人が何を確かめてから誰が行うかを読む。「下書きまではAI、宛先と本文を確認して担当者が送信」のように境界を示すと、意図しない実行を避けやすい。 |
| 秘密の情報 | パスワード・APIキー・個人情報の候補があれば、値や値の一部を出力・修正案に写さない。行番号と値を含まない説明だけを示す。依頼文には権限の参照名や伏せ字を使い、必要な認証情報は承認済みの秘密管理手段で渡すよう案内する。 |
| 読み手 | 会話を知らない相手でも、誰が何をするか、どの対象を指すかが分かるか。主語・目的語がなくても前後から一意なら補足は不要。複数の読み方がある文は行を示し、担当者や対象を尋ねる。 |
| 書式 | 利用者から決まった書き方の一覧を受け取ったときだけ、対応する行を調べ、説明の付け足しや表記の揺れを示す。揃った書式は読み手が値を拾う助けになる。一覧がなければ省く。 |
| 長さ | お礼、敬語の前置き、経緯が本文の大半を占めていれば、目的・範囲・受け入れ条件を先に置くよう勧める。判断に必要な経緯は後ろに残す。 |

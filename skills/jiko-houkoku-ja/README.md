# jiko-houkoku-ja

日本の会社で起きた1件の業務事故・障害を、個人を責めずに、原因と再発防止策をまとめた社内報告書にするスキルです。社外に影響があれば、お客様・取引先へのお詫び・お知らせを別に下書きします。総務・経理・店長・経営者など、技術の専門家でない担当者が使うことを想定しています。

メールの誤送信、請求・発注の誤り、書類や端末の紛失、クラウドの設定の誤り、利用中のサービス停止を扱います。入力は利用者が渡すメモ・やりとりの記録・時系列の文章だけです。メール・チャット・監視のサービスには接続せず、送信・公表・ファイルの書き換えもしません。

## 決まり

| 項目 | 扱い |
| --- | --- |
| 事実 | 材料にない時刻・件数・金額・人名・原因を作らない。未確認には確認担当を付ける |
| 時系列 | 起きた・気付いた・止めた・元に戻した・お客様に知らせた、を分ける。記録のない時間帯を示す |
| 経過時間 | 気付くまでと、気付いてから止めるまでを分け、起点不明なら計算しない |
| 原因の候補 | 6分野ごとに確認済み・疑い・否定を区別し、根拠を書く。該当しない分野は空にする |
| なぜの掘り方 | 人の誤りで止めず、その状態が起きうる仕組みの欠けを調べる。個人名を原因の主語にしない |
| 原因の整理 | 引き金・根本原因・悪化させた要因を分ける。根本原因は複数でもよい |
| 再発防止策 | 徹底・確認・教育だけにせず、変更内容・種類・担当1人または1人の役割・期限・完了の確かめ方を書く |
| 発見の遅れ | 遅れがあった事故には早く気付く対策を1つ以上入れる |
| 社外 | 社内とは別文書にし、事実・影響・お願いすること・問い合わせ先・今後の対応を書く。内部の原因分析と個人名を入れない |
| 個人情報 | 可能性があるときや不明のときは、報告書冒頭で個人情報保護委員会の公式案内の確認と必要なら専門家への相談を促す。要否・期限は判断しない |
| 表記 | 常体、日付と曜日、24時間表記。対策の案と合意済みの内容を区別する |

項目ごとの理由は [report-rules.md](references/report-rules.md)、入力形式と型は [templates.md](references/templates.md) にまとめています。

## 入れ方

`skills/jiko-houkoku-ja/` を、利用するAIエージェントのスキル用フォルダーへフォルダーごとコピーします。`LICENSE` も含めてください。同名のフォルダーがある場合は、内容を確認してから上書きするか決めます。他のスキルは必須ではありません。

点検スクリプトにはPython 3.9以上を使います。標準ライブラリだけで動き、追加依存はありません。

## 使い方

```text
jiko-houkoku-jaで、次のメモから事故の社内報告書を作ってください。
これは架空の事故です。取引先に影響があり、個人情報の有無は未確認です。
分からない点は最大3つずつ質問し、分からないままの点は確認担当つきで残してください。
社外のお詫び・お知らせは別の下書きにし、会話内で返してください。
続けて概要・影響・時系列と手がかりを渡します。
```

既存の報告書の点検例（リポジトリのルートから実行）：

```bash
python3 skills/jiko-houkoku-ja/scripts/check_report.py skills/jiko-houkoku-ja/examples/01-before.md --external skills/jiko-houkoku-ja/examples/01-external-before.md --name 架空担当甲
python3 skills/jiko-houkoku-ja/scripts/check_report.py skills/jiko-houkoku-ja/examples/01-after.md --external skills/jiko-houkoku-ja/examples/01-external-after.md --name 架空担当甲
```

点検は定型Markdownを対象にし、自由形式の材料を直接渡すものではありません。見出しと表を [型](references/templates.md) に合わせてください。ファイルの読み取りと標準出力だけを行い、入力文・ファイル名・登録人名は再掲しません。会話の下書きを点検のために保存する場合は、利用者が内容と保存先を確認した別の操作として行い、このスキルでは保存しません。

表示は、機械的な修正候補が「×」、人が意味を確かめる候補が「△」です。検出0件なら終了値0、どちらかがあれば1、引数・入力の誤りは2です。0件でも最後に人が確かめる点を表示します。`--external` を指定しなければ社外文面は点検せず、`--name` に登録しない人名は検出しません。表記違いを推測しないので、確認済みの各表記を登録してください。

## 架空の素材と試した結果

条件：GPT-6（Codex）が架空の事故3本の材料と、各事故の社内報告書・社外下書きの修正前後を作りました。同じモデルがPythonスクリプトを実行し、材料と文書を手動照合しました。修正前はAIが書きがちな問題を意図して埋め込んだ例であり、実際のAI利用から集めた失敗例ではありません。会社・人物・出来事・件数・金額はすべて架空です。

### 機械点検

社内報告書6本と別文書の社外下書き6本、合計12文書を、事故・修正段階ごとに組み合わせた6回の実行で確認しました。各回で `--name 架空担当甲` を登録しました。件数は検出項目の一致数で、報告書の評価点ではありません。同じ行の欠落と未確認が重なる場合があり、同じ未確認が複数箇所にあればその都度数えています。

| 架空の材料 | 修正前（社内＋社外） | 修正後（社内＋社外） | 修正後に残したもの |
| --- | --- | --- | --- |
| [01 メールの誤送信](examples/01-material.md) | [社内13](examples/01-before.md)＋[社外4](examples/01-external-before.md)＝17件 | [社内5](examples/01-after.md)＋[社外1](examples/01-external-after.md)＝6件 | 個人情報・転送・回収状況の未確認 |
| [02 請求書の金額の誤り](examples/02-material.md) | [社内8](examples/02-before.md)＋[社外3](examples/02-external-before.md)＝11件 | [社内2](examples/02-after.md)＋[社外0](examples/02-external-after.md)＝2件 | 記録のない時間帯の訂正作業の未確認 |

不明なことを材料なしに確定しないため、修正後も検出を残しました。件数の変化は、この意図的に作った素材と検出規則の組み合わせの結果であり、事故や作成時間の減少、文章の品質の改善を測ったものではありません。

### 例ごとの手動照合

| 例 | 原因が人の誤りで終わっていないか（前→後） | 対策に担当と期限があるか（前→後） | 社外に社内分析が混ざっていないか（前→後） |
| --- | --- | --- | --- |
| 01 | 不注意・確認不足で終わる→宛先と添付の対応確認、送信後の確認役割の欠けまで記載 | 抜け→3対策に1人の役割と2026-11-13（金）、完了条件を記載。早く気付く対策あり | 根本原因と架空担当甲の名前が混在→除去し、影響の未確認は残した |
| 02 | 不注意・確認不足で終わる→単価更新と発行前照合の欠けまで記載 | 抜け→1対策に経理責任者と2026-11-13（金）、完了条件を記載 | 根本原因と架空担当甲の名前が混在→除去し、訂正版の金額とお願いを残した |
| 03 | 不注意・確認不足で終わる→定時確認と紙への切替基準の欠けを記載。外部サービスの原因は確定せず | 抜け→2対策に1人の役割と2026-11-13（金）、完了条件を記載。早く気付く対策あり | 根本原因と架空担当甲の名前が混在→除去し、オンライン申込への影響は未確認とした |

材料の時刻・件数・金額、5段階の時系列、記録のない時間帯、引き金・根本原因・悪化要因の分離、候補の確認済み・疑い・否定・空欄も照合しました。社外への敬語を整えた正式文書や、送信・公表は確認していません。

## 線引き

`jiko-houkoku-ja` は1件の事故・障害の社内報告書と、社外へのお詫び・お知らせの下書きだけを扱います。打ち合わせの議事録は同じスキル集の `gijiroku-ja`、全社への周知の文面は `internal-notice-ja` に任せます。他のスキルを呼び出すことを必須にはしません。

## 分かっていないこと・範囲外

- 実際の事故の記録や不足のある資料との対話は未検証です。長い時系列、多数の関係者、異なる時刻基準を含む記録も未検証です。
- 業種ごとの報告の慣習、社内の承認経路、法令上の報告との関係は未検証です。
- 個人情報の漏えい等に関する報告の要否・期限の判断、法的助言、セキュリティの調査・フォレンジック、攻撃の手順、公表の判断は範囲外です。個人情報の可能性があれば、[個人情報保護委員会の公式案内](https://www.ppc.go.jp/personalinfo/legal/leakAction/) を利用者が確認し、必要なら専門家に相談します。
- 検査は単語と定型表による候補の表示です。引用・否定・類義語、未登録の人名、具体的な語を含むだけの弱い対策は見逃しや過剰検出があります。日付は型の形式を対象とし、営業日・祝日の計算はしません。
- 0件でも原因の正しさ・対策の効き目・社外への説明の適切さは保証しません。渡された材料と人の判断が必要です。実際の事故の減少、作成時間の短縮、独立した評価者による品質評価は測定していません。

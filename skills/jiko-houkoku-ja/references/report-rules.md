# 報告書の決まりと理由

| 項目 | 決まり | 理由 |
| --- | --- | --- |
| 材料と未確認 | 材料にない時刻・件数・金額・人名・原因を作らない。不明は未確認とし、確認担当を付ける。担当も不明なら未確認とする | 空欄をもっともらしく埋めると、その後の判断の前提が変わるため |
| 段階 | 起きた・気付いた・止めた・元に戻した・お客様に知らせた、を別行で書く。不明・該当なしも理由とともに残す | 発見、被害の抑制、業務の復旧、連絡は別の出来事であるため |
| 経過時間 | 起きてから気付くまで、気付いてから止めるまでを分ける。記録のない時間帯を示す。起点不明なら算出しない | 気付きの遅れと初動の遅れでは必要な対策が違うため |
| 候補の広さ | 作業の手順／使っている道具とその設定／確認の仕組み／人の配置と引き継ぎ／外部のサービス・委託先／気付く仕組み、の6分野を並べる | 最初に思い付いた1つの説明へ偏るのを避けるため |
| 候補の状態 | 確認済み・疑い・否定と、材料の出所を付ける。当てはまらない分野の候補・状態・根拠は空にする | 調べて否定した候補と、材料がなく挙げていない分野を混同しないため |
| なぜの掘り方 | 有力な候補について、なぜその状態が起き得たかを掘る。回数は固定せず、根拠がなければ疑いとする | 根拠のない物語を原因として確定しないため |
| 責めない書き方 | 不注意・確認不足・うっかり・ミスで止めない。個人名を原因の主語にしない。「担当者が忘れた」でなく、根拠があれば「送信前に宛先を確かめる手順がなかった」と書く | 個人の性質で終えると直せる条件が見えなくなるため。仕組みの欠けも材料なしに断定しない |
| 原因の整理 | 引き金（直接のきっかけ）、根本原因（直せる仕組みの欠け）、悪化させた要因を分ける。根本原因は複数可 | 起きた理由と被害が広がった理由を同じ対策で済ませないため |
| 対策 | 注意の徹底・ダブルチェック・教育だけにせず、何をどう変えるか、種類、担当1人または1人の役割、期限、完了の確かめ方を書く | 誰が何を終えれば対策が完了するか分かる形にするため |
| 対策の種類 | 早く気付く／被害を小さくする／起きないようにする。発見が遅れた事故では早く気付く対策を1つ以上入れる | 発見が遅れた要因を対策から落とさないため |
| 案と合意 | 未合意の対策・担当・期限は提案と明記し、不明の担当や期限は未確認とする | 報告書を作っただけで仕事の割り当てや承認が成立しないため |
| 社内と社外 | 別文書にする。社外は事実・影響・お願いすること・問い合わせ先・今後の対応に絞り、社内分析と個人名を入れない。未確認を確定として書かない | 説明する相手に必要な情報と、内部で検討する情報の混在を避けるため |
| 個人情報 | 含まれる可能性がある場合、冒頭に下記の案内を表示する。不明の場合も表示する。報告の要否・期限は判断しない | 法的な判断を文章作成スキルが代行しないため |
| 表記 | 常体。日付はYYYY-MM-DD（曜）、時刻は24時間。日またぎでは各行に日付。異なる時刻基準は確認する | 日付の取り違えや時刻だけの比較を避けるため |
| 最後の確認 | 機械点検後も材料との一致、原因の根拠、対策の実行可能性、説明の適切さを人が確認する | 単語の検出や形式点検では意味や妥当性を判断できないため |

個人情報の可能性がある報告書の冒頭に表示する文：

> 個人情報保護委員会への報告や本人への通知が必要か、公式の案内（https://www.ppc.go.jp/personalinfo/legal/leakAction/ ）を確かめ、必要なら専門家に相談する

このスキルは公式案内を自動取得せず、利用者が確認する先として示す。報告義務・期限の判定、法的助言、セキュリティの調査・フォレンジック、公表の判断は範囲外である。

# 構成・デザイン・日本語の決まり

## 構成の型

| パート | 見本のページ | 書くこと | 理由 |
| --- | --- | --- | --- |
| 結論 | 表紙、ご提案の要点 | 対象、方針、判断してほしいこと | 決裁者が読む目的を先に把握できる |
| 問題提起 | 現状の確認2枚、課題の整理 | 相談で確認した事実、未確認事項、原因と方針 | 推測と事実が混ざるのを防ぐ |
| 解決策 | 全体像、内容、進め方、見積り | 今と提案後の業務の流れ、範囲、工程、費用の条件 | 実際に何が変わるかを判断できる |
| 信頼 | 会社紹介 | 掲載許可のある体制・実績の要点 | 実施できる根拠を確かめられる |
| 安心 | よくあるご質問、今後の進め方 | 対象外、未確定条件、冒頭の判断事項と次の連絡 | 認識違いを残さず判断につなげる |

個別の営業事例・ノウハウを定型化しない。事実が足りなければ「要確認」を残す。

## 見た目と紙面

| 決まり | 理由 |
| --- | --- |
| カッコよさを目的にせず、白のほかは3色まで | 色の意味を追いやすくする。初期値は文字・強調・注意の3色で、ほかは灰色だけ |
| ゴシック体。Macはヒラギノ、Windowsはメイリオ、LinuxはNoto Sans JP | 日本語の本文と図表を同じ調子で読める。Webフォントは取得しない |
| 会社の見た目を設定後、提案先ごとにデザインを変えない | 内容の比較を邪魔せず、部品を再利用するため |
| タイトルは左上、ロゴは右上、番号は右下に固定。表紙にはタイトルとメッセージを置かない | 読者が位置を探し直さずに済む。表紙は提案先と件名だけを読ませる |
| 枠を増やすより整列・近接・余白で区切る | 関連する情報と別の情報を区別できる |
| 下の4割が空くページを作らない | 情報を上に詰めず紙面を使う。装飾で埋めず図表の配置や余白を見直す |
| ページごとに比較・表・数字など組み方を変える | 情報の関係に合わせて読める。毎回同じカードに押し込めない |
| 解決策に今と提案後の業務の流れを1枚置く | 変更する工程と人の役割を説明できる |
| 自動処理は塗り・太い枠・文字を併用する | 色の区別が難しくても意味が分かる |

## 文字の大きさ

| 用途 | 大きさ | 理由 |
| --- | --- | --- |
| メッセージ | 28pt | そのページの結論を先に読める |
| 小見出し・ページタイトル | 22pt | 結論と本文の階層を分ける |
| 本文 | 20pt | 画面共有で縮小されても読める大きさを確保する |
| 表と図 | 18pt | 比較する項目を並べても読める |
| 注記・ページ番号 | 15pt | 条件を本文と区別しつつ読めるようにする |

表紙の件名と大きな数字・金額だけはさらに大きくする。実際の共有画面での可読性は別途確認が必要。

## 組版

| 決まり | 理由 |
| --- | --- |
| `line-break: strict` で句読点・閉じカッコの行頭を避ける | 行の始まりが読みにくくならないようにする |
| 見出し・メッセージ・表の見出しは `word-break: auto-phrase` | 文節の途中で切れるのを避ける。未対応ブラウザでは意味の切れ目に `<br>` を置いて目視確認 |
| 見出しだけ `font-feature-settings: "palt"` | 約物周辺を整える。本文の字幅まで変えない |
| `text-autospace: ideograph-alpha` | 和文と欧文の間だけを空け、数字の前後を空けない。未対応時も数字の前後に手入力の空白を足さない |
| 金額は右寄せ、`font-variant-numeric: tabular-nums` | 桁を比較できる。等幅数字の対応はフォントに依存するため目でも確かめる |

CSSへの対応や禁則処理はブラウザ・フォントにより異なる。固定高の `overflow: hidden` は余分な内容を隠すため、全ページを画像で確認する。

## 表記と言い回し

| 決まり | 理由 |
| --- | --- |
| タイトルは「現状の確認」「お見積り」など普通の言葉 | キャッチコピーから内容を推測する負担を避ける |
| 項目の数を3つにそろえない | 内容の欠落や水増しを避ける。必要な結果が3項目ならそのままでよい |
| 効果を約束しない。傾向には出典を付ける | 実測と仮説を区別するため |
| メッセージは句点なしの1文。「A。B」の二段構えにしない | 結論をひとまとまりで読める |
| 事実と判断を1文に入れ、まず1行で書く | なぜその判断かを示す。42字は点検の目安で、収まりは実際の画面で確認 |
| 隣り合う3枚で同じ文型を続けない | 単調な繰り返しで意味の差が埋もれるのを防ぐ |
| 要素の数え上げ・自己言及・ダッシュをメッセージに使わない | 「3つのポイント」「本資料では」などで結論を置き換えないため |

`check_messages.py` は文末4字の一致などによる候補表示であり、日本語の文型・事実・判断を理解した判定ではない。指摘がなくても人が確認する。

## ストーリーと事故の防止

| 確認 | 理由 |
| --- | --- |
| メッセージだけ縦に読み「だから」「なぜなら」でつなぐ | ページ間の論理の飛躍に気づくため |
| 言い分を支える本文の要素を対応させる | 根拠のない断定を残さないため |
| 結論のページで判断事項を予告し、最後で回収する | 読み終えた人が何を決めるか分かるため |
| 提案先・件名・日付は先頭の変数だけで変更する | 差し替え漏れを減らす。旧名・旧数字は別途全文検索する |
| ページ番号はCSSカウンターで自動化する | ページ追加時の振り直し漏れを避ける |
| 「要確認」は破線の枠と文字で示す | 色に頼らず未確定と分かるため |

## 色の差

WCAGの相対輝度の式 `(明るい色の輝度 + 0.05) / (暗い色の輝度 + 0.05)` で計算する。初期値で実際に文字に使う組み合わせは次のとおり（小数第2位に丸め）。すべて4.5:1以上。色を差し替えたら再計算する。

| 文字 | 背景 | 比率 |
| --- | --- | --- |
| `#222222`（本文・見出し） | `#ffffff` | 15.91:1 |
| `#365e70`（強調・番号・ご提案後） | `#ffffff` | 7.02:1 |
| `#8a5b13`（要確認・問題の作業） | `#ffffff` | 5.86:1 |
| `#5e5e5e`（補足・注記・ページ番号） | `#ffffff` | 6.48:1 |
| `#222222`（自動の作業の文字） | `#e8eff2` | 13.68:1 |
| `#5e5e5e`（自動の作業の補足） | `#e8eff2` | 5.58:1 |
| `#ffffff`（「自動」の札） | `#365e70` | 7.02:1 |

上の組み合わせ以外で、色の付いた背景の上に文字を重ねない。ロゴを差し替えた場合も確認する。

# 日本語の提案書を作る

外部フォント・画像・スクリプトを取得しない。添付の架空の会社名・数字を実案件の事実として使わない。外部への送信や公開は行わない。

## 1. 材料を集める

提案先の名前、相談内容、提案すること、期間、金額、掲載してよい事例・担当者を、提供済みの材料から拾う。足りないものだけ利用者に聞く。数字・実績・事例・効果を推測で埋めず、未確認の箇所は「要確認：確認する内容」として残す。一般的な傾向を根拠にするなら出典を示す。掲載許可のない情報は入れない。

## 2. HTMLより先にストーリーを決める

[構成と組版の決まり](references/design.md)を読み、全ページの「ページのタイトル」「メッセージ（そのページの結論）」「前のページとのつながり」「本文の根拠」の一覧を提示する。表紙にはメッセージを置かない。結論→問題提起→解決策→信頼→安心の順に組み、冒頭の判断事項を最後で回収する。

メッセージだけ縦に読んで「だから」「なぜなら」でつながるか、事実と判断が同じ1文に入るかを確かめる。**利用者の了承を得るまでHTMLを作らない。**

## 3. テンプレートに中身を入れる

出力先と作成するファイルを利用者に確かめてから、`assets/template.html` と `assets/logo.svg` を同じ出力フォルダーへコピーする。既存ファイルを確認なしに上書きしない。

提案先・件名・日付はHTML先頭のCSS変数だけで変更する。色とフォントも同じ設定欄で管理する。会社の見た目を設定する必要がある場合は、利用者が提供・使用を許可したロゴを使い、色の差を再計算する。提案先ごとにレイアウトを作り直さない。

本文はテンプレートの番号付き要点・数字・比較・表・業務の流れ・ガント・金額・質問・連絡先・要確認・注記の部品を使う。新しい見た目を作らず、情報が入らないなら文章を減らすかページを分ける。文字を小さくして詰め込まない。

## 4. 文面を点検する

`references/design.md` の表記と言い回しを点検し、次を実行する。

```bash
python3 scripts/check_messages.py <出力先>/proposal.html
```

候補を人が判断し、機械が指摘しなくても根拠と判断を確認する。同じリポジトリの `ai-smell-ja` が使える場合は追加で点検する（なくても進められる。ファイルは共有しない）。置き換え前の提案先名・件名・日付・金額・件数を検索し、HTML本文・設定欄・ロゴ・注記に残っていないか確かめる。

## 5. PDFにして全ページを確かめる

PDFの出力先も確認したうえで実行する。

```bash
python3 scripts/build_pdf.py <出力先>/proposal.html --out <出力先>/proposal.pdf
```

同名ファイルは上書きしない。上書きの了承がある場合だけ `--force` を使う。ブラウザが見つからなければ `--browser <実行ファイル>` を指定する。スクリプトは静的HTMLと同じフォルダーの自己完結したSVGだけを扱う。

PDFのページ数をHTMLと照合する。PDFを画像にして、**全ページ**の文字切れ・はみ出し・不自然な改行・図表の読順・金額の桁・判断事項の予告と回収を目で確かめる。スライドの高さは固定で、はみ出した中身は隠れる。ページ数の一致だけでは欠落を検出できない。画像化ツールがなければ利用者にPDFの全ページ確認を依頼し、確認済みと書かない。

## 6. 報告する

作ったHTML・ロゴ・PDF、残る「要確認」と確認担当、実施した確認、確かめられなかったことを報告する。効果や品質を保証しない。送信・公開は別途利用者が行う。

# x-post-check-ja

日本の中小企業が会社のXアカウントで出す原稿を、公開前に点検するスキルです。利用者が渡した1本または複数本を読み、直す点（×）、気になる点（△）、直した案、人が確かめる点を返します。投稿・予約・Xへの接続はしません。

## 決まりの一覧

- 1投稿1メッセージ。日本語で120字程度までを目安にする。
- 1行目は読み手の困りごと・意外な事実・言い切った答え。記事の題名や社名・「当社が〜」で始めない。
- 「〜で困っていませんか？」「〜を紹介します」などの書き出しを続けない。
- 注意書きは結果・数字を書く投稿だけ、末尾に1つ。必要な条件は削らない。
- リンクは最後に1つ。前に空白か改行を置き、本文だけでも得るものを残す。返信には付けない。
- ハッシュタグは0〜1個、絵文字は使わない。
- 「必ず」「〇倍」「誰でも」「〜が不要になる」など、効果・実績・保証を言い切らない。
- 社内の略語・ツール名・段階名を読み手の言葉にする。
- 加重文字数の概算が280を超えたら表示する。

理由は [rules.md](references/rules.md)、4種類の型と修正前後の見本は [pillars.md](references/pillars.md) を参照してください。これらは編集方針であり、配信順位の条件ではありません。

## 入れ方

スキルを読み込めるAIエージェントと、補助スクリプト用のPython 3.9以上を使います。Pythonの標準ライブラリだけで動き、追加の依存は不要です。

CLIを利用する場合は、Node.js 22.20以上とnpxが使える環境で、導入先・利用するエージェントを確認してから実行してください。

```bash
npx skills add hirosta/skills --skill x-post-check-ja
```

CLIには匿名の利用集計があります。無効にする場合は `DISABLE_TELEMETRY=1` を付けます。手で導入する場合は、このリポジトリから `skills/x-post-check-ja/` をフォルダーごと利用するエージェントのスキル置き場へコピーしてください。同名のフォルダーがあれば、内容と上書きの可否を先に確認してください。

## 使い方

スキルを読み込んだエージェントに、原稿と、分かれば種類・一次資料・社内語一覧を渡します。

```text
x-post-check-jaで、次の会社のX原稿を出す前に点検してください。
種類は「やってみた」です。添付の試作メモを根拠にしてください。
直す点（×）、気になる点（△）、直した案、人が確かめる点を返してください。
（ここに原稿を貼る）
```

機械確認だけなら、リポジトリのルートから次を実行します。1ファイルが1投稿で、本文内の改行はそのまま扱います。入力はUTF-8（BOM付きも可）。ファイル末尾の改行は原稿から除きます。

```bash
python3 skills/x-post-check-ja/scripts/check_post.py skills/x-post-check-ja/examples/article-1-before.txt
python3 skills/x-post-check-ja/scripts/check_post.py --internal-terms skills/x-post-check-ja/examples/internal-terms.txt skills/x-post-check-ja/examples/article-1-after.txt
python3 skills/x-post-check-ja/scripts/check_post.py --internal-terms skills/x-post-check-ja/examples/internal-terms.txt skills/x-post-check-ja/examples/article-*-before.txt
```

`--internal-terms` は任意です。1行1語、空行は無視し、重複は除きます。指定した一覧そのものと原稿内の一致を表示します。一覧がなくても原稿の点検はできますが、未知の社内語は推定しません。

出力には原稿の1行目と検出した文字列が含まれます。公開先に貼る前に内容を確認してください。ファイルの読み取りと標準出力だけを行い、ネットワーク接続・ファイルの書き換え・投稿・予約はしません。

終了値は、検出なしが **0**、×または△が1件以上あれば **1**、引数・読み取り・空の入力などの誤りが **2** です。検出0件は内容の合格ではありません。種類ごとの意味や事実は、人またはスキルを読み込んだエージェントが読む必要があります。最後に必ず次を表示します（`--help` を除く）。

> 1行目で手が止まるか、事実が一次情報と合っているかは人が読んで確かめる

会話の原稿をファイルに保存する場合は、利用者に内容と保存先を確認する手順です。保存・実行の確認が得られなければ読み取りだけで点検し、機械確認は未実施と報告します。事実の日付・数字・発表元は推測で直さず、利用者がリンク先・公式発表と照合してください。

## 数え方と制約

参照日：**2026-11-12**。[X公式の文字数の説明](https://docs.x.com/fundamentals/counting-characters) と [twitter-textのv3設定](https://github.com/twitter/twitter-text/blob/master/config/v3.json) を確認しました。コードや例文は転載していません。

- 通常の上限は加重280字、検出したURLは長さにかかわらず23字。120字程度という編集目安とは別です。編集目安にはURLも実際の長さで含めます。
- NFCで正規化して計算します。重み1は U+0000〜U+10FF、U+2000〜U+200D、U+2010〜U+201F、U+2032〜U+2037、その他は原則2です。「全角2・半角1」は大まかな説明で、半角カナなどには例外があります。空白・改行も含みます。
- URLはHTTP(S)表記と、ASCIIのドメイン形式を簡易検出します。[公式のパス文字の規則](https://github.com/twitter/twitter-text/blob/master/js/src/regexp/validGeneralUrlPathChars.js)と[クエリ文字の規則](https://github.com/twitter/twitter-text/blob/master/js/src/regexp/validUrlQueryChars.js)を参考に、ホスト・パス・クエリをASCIIの文字に限定し、直後の日本語・句点・絵文字は本文として扱います。末尾の一般的な句読点は除きます。公式のURL抽出と同一ではありません。日本語など非ASCIIのパス・クエリはパーセント符号化した原稿で確認してください。国際化ドメイン、アクセント付き文字・キリル文字、括弧を含むパス、未知のTLDやドメインに似た本文は過不足がありえます。リンク数・位置・文字数にも影響します。
- 絵文字は範囲と単純な連結・肌色・国旗・キーキャップを使う概算です。記号を絵文字と数える場合、新しい絵文字・タグ列を拾えない場合があります。結合文字や特殊な文字も含め、公式の厳密な実装と一致する保証はありません。上限付近ではXの入力画面で確認してください。
- ハッシュタグは `#` または `＃` に続く文字・数字・アンダースコアを数える簡易判定。注意書き・保証表現は文字列の一致です。否定・引用も拾い、言い換えは見逃します。
- 投稿の可否、必須の法的表示、リンク先の内容、事実の正しさ、読み手の関心はスクリプトでは判定しません。添付メディア、長文投稿、返信時に自動で付くメンションの除外も扱いません。

## 試した結果

条件：GPT-6（Codex）が作成・書き直しした架空の素材12本（4種類×3本）、修正前後の計24ファイルです。[架空の前提資料](examples/context.md)を使い、実在の投稿は写していません。Python 3.12.4で実行し、種類ごと・修正前後ごとに3ファイルを同時に渡し、[社内語一覧](examples/internal-terms.txt)を指定しました。独立した読み手や別モデルによる評価はしていません。

件数は検出項目の一致数であり、投稿の良し悪しの点数ではありません。原稿のまとめ方や社内語一覧が違うと件数も変わります。

| 種類（各3本） | ファイルの接頭辞 | × 前 → 後 | △ 前 → 後 |
| --- | --- | --- | --- |
| 注意 | `examples/notice-1` 〜 `notice-3` | 12 → 0 | 12 → 1 |
| やってみた | `examples/trial-1` 〜 `trial-3` | 12 → 0 | 17 → 0 |
| 読み物 | `examples/article-1` 〜 `article-3` | 10 → 0 | 12 → 0 |
| 返信 | `examples/reply-1` 〜 `reply-3` | 8 → 0 | 9 → 0 |
| 合計 | 各接頭辞に `-before.txt` / `-after.txt` | 42 → 0 | 50 → 1 |

注意の修正後に残る△は `notice-1-after.txt` の「棚メモ」です。社内語一覧にありますが、発表対象の商品を特定するため残しました。検出を0件にすることは目標にしません。日付・発表元・数値・条件を前提資料と照合し、根拠のない保証や批判は削除しました。試作の意外な点と記事の答えは前提資料から出し、返信は架空の相手の発言を受ける2文にしました。

### 手で数えた加重値との比較

通常の文字とURLを使った次の5本を、作成した同じAIが手計算し、スクリプトの関数の出力と比べました。すべて一致しました。自動テストは同梱していません。

| 原稿（改行を含まない） | 手計算 | スクリプト |
| --- | --- | --- |
| `ABC123` | 6 | 6 |
| `備品を返す` | 5文字×2 = 10 | 10 |
| `備品 A1` | 2文字×2＋空白1＋英数字2 = 7 | 7 |
| `確認 https://example.invalid/a` | 2文字×2＋空白1＋URL23 = 28 | 28 |
| `ｶﾅ` | 半角カナ2文字×2 = 4（公式範囲定義の例外） | 4 |

追加の手動確認では、加重280字ちょうどで上限超過が出ず、282字では×が出ること、改行前後のリンク位置、複数リンク、隣接するタグ、注意書きの位置を確認しました。BOM付きの原稿で終了値0、検出ありで1、空・不正UTF-8・存在しないファイル・先頭空行・引数誤りで2を確認しました。スクリプトは標準ライブラリだけで実行しました。

URL境界の修正時には、GPT-6（Codex）が架空の原稿「確認はこちら https://example.invalid/a。必ず安心😊」を手動確認しました。URLを `/a` までと抽出し、リンクの位置・絵文字の×が2件、保証表現の△が1件、終了値1となりました。加重値は本文7文字×2＋空白1＋URL23＋句点と「必ず安心」5文字×2＋絵文字2＝48で一致しました。句点なしの日本語の隣接、パスなし、スキームなし、クエリ・フラグメント後の本文でも同じ3項目を検出しました。ASCIIのクエリ・フラグメントとパーセント符号化を含む末尾URLは1個として扱いました。

### 分かっていないこと・範囲外

- **実際の効果**：表示回数、反応、フォロワー、作業時間、読み手が1行目で手を止めるかは測っていません。件数の減少から効果を推定しません。
- **特殊な文字**：絵文字・特殊な結合文字・複雑なURLの全パターンと公式実装の一致は未確認。概算であり、偽陽性と見逃しがあります。
- **仕様変更**：参照日以降のXの変更への追従は保証しません。投稿の直前は利用者が公式資料と入力画面を確認してください。
- 法的助言・セキュリティ判断、一次情報の自動取得、投稿・予約・画像生成は範囲外です。外部リンクや類似投稿が届きにくいという未確認の話は、このスキルの根拠にはしていません。

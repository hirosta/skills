# 種類ごとの型と架空の見本

会社・商品・出来事・会話はすべて架空。`example.invalid` は説明用の行き先であり、発表の根拠として使わない。注意の見本は、下記の架空資料が利用者から渡された想定。実際の原稿では利用者が公式発表と照合する。

## 注意（セキュリティ・制度の更新など）

何が起きたか（発表元・日付）→読み手がすること1つ→公式発表のリンク。することは公式発表に書かれたものだけ。

架空資料：こもれび試作室の架空サービス「棚メモ」の発表（2026年10月1日）に「設定画面で通知先を確認する」とある。

**前**

```text
当社から棚メモの大切なお知らせをご紹介します！設定確認で誰でも安心です。詳しくはこちらhttps://example.invalid/notice #更新 #安心
```

**後**

```text
棚メモの通知先の確認が必要です。
こもれび試作室が2026年10月1日に発表。設定画面で通知先を確認してください。
https://example.invalid/notice
```

直した点：発表元・日付・資料にある行動1つを残し、保証・タグの重なりを削除。

## やってみた（試作・事例）

意外だったこと→分かったこと1つ→結果・数字があれば注意書き1つ→リンク（共有先がある場合）。結果の範囲を消さない。

**前**

```text
当社の試作をご紹介します！棚メモなら必ず確認が速くなり、誰でも手戻りが不要になる！試作では確認漏れが2件ありました。（社内の試作です）（条件で異なります）https://example.invalid/trial
```

**後**

```text
色分けだけでは確認漏れを防げませんでした。
棚メモの試作で確認漏れが2件あり、文字の目印も必要だと分かりました。
（社内の試作の結果です）
https://example.invalid/trial
```

直した点：架空の観測結果と条件を保ち、一般への保証を削って分かったことを1つに整理。

## 読み物（記事の告知）

記事の答えを先に1つ言い切る→誰のための記事か→リンク。題名の貼り付けや記事の存在だけの紹介にしない。

**前**

```text
備品管理で困っていませんか？「備品管理の改善方法を紹介します」という記事を公開しました！ぜひご覧ください！https://example.invalid/article #備品 #管理
```

**後**

```text
返却場所は、借りる場所と同じにします。
備品の戻し忘れに悩む小さな事務所向けに、置き場の決め方を書きました。
https://example.invalid/article
```

直した点：架空の記事で述べた答えを先にし、対象読者を明示してリンクを最後に整理。

## 返信

相手の話を受ける→具体例か確かめ方を1つ足す。2〜3文で宣伝・リンク・批判をしない。

架空の相手の発言：「返す棚が分からず、備品を机に置いてしまいます」。

**前**

```text
それは管理が悪いですね。当社の棚メモなら必ず解決します！https://example.invalid/product
```

**後**

```text
返す棚が分からないと、机に置いてしまいますね。
棚と備品に同じ名前の札を付ける方法はどうでしょうか。
```

直した点：批判と宣伝を削り、相手の困りごとに沿った具体例を1つ追加。

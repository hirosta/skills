# 決まりと理由

これは一般の会社向けの編集上の目安。Xの配信順位を予測する決まりではない。×は明確に直す箇所、△は文脈や根拠を人が確かめる候補。スクリプトの検出は補助であり、読んだ判断と区別して報告する。

| 決まり | 理由と読み方 |
| --- | --- |
| 1投稿1メッセージ。日本語120字程度まで | 読み手が持ち帰ることを1つに絞る。別の要点があれば分けるか削る。120は加重値ではなく、改行・URLも含む原稿の文字数の目安（△）。短くても2つ言っていれば直す。 |
| 1行目は困りごと・意外な事実・言い切った答え | 記事の題名や説明文をそのまま置かず、本文で得られることから始める。「株式会社こもれび試作室が発表」「当社が実施」で始めない（社名は架空）。答えを言い切ることと、効果を保証することは別。 |
| 同じ型の1行目を続けない | 「〜で困っていませんか？」「〜を紹介します」を続けると原稿間の違いが伝わりにくい。複数本では同じ書き出しを表示。機械は先頭8文字の一致と上の2つの型を△にする。意味の重なりや連続順は人が読む。 |
| 注意書きは結果・数字がある投稿だけ末尾に1つ | 結果の適用範囲を残し、断り書きの重なりを避ける。例「（社内の試作の結果です）」。本文→注意書き→タグ（任意）→URLの順。日付だけなら機械は結果の数字と扱わない。必須条件は消さず、人が整理できるまで公開保留。 |
| リンクは最後に1つ、URLの前に空白か改行 | 本文と行き先を区切る。リンクがなければ得るものがない本文は直す。リンク数・空白・位置の違反は×。リンクが必須かは種類で判断し、返信には付けない。 |
| ハッシュタグ0〜1個、絵文字なし | 読み手が追う要素を絞る編集方針。タグ2個以上・絵文字は×。Xの禁止事項や配信に有利な条件という意味ではない。 |
| 効果・実績・保証を言い切らない | 「必ず」「〇倍」「誰でも」「〜が不要になる」は根拠と条件の確認が必要（機械は△）。数字の実績が確認できても一般への保証に広げない。否定・引用でも拾うので文脈を読む。 |
| 社内語を読み手の言葉へ | 略語、社内ツール名、作業段階の名前は用途が分かる説明にする。利用者の一覧は表示し、原稿中の一致を△にする。一覧がなくても人が読む。機械は未知の略語や社名を推定しない。 |
| 加重280字を超えたら表示 | Xの通常の文字数上限と編集目安を分ける。全角2・半角1・URL23は大まかな説明で、実際はUnicode範囲別の重み。概算が280超なら×。280以下でも公式入力画面で確認する。 |

## 機械検出の境界

- 注意書きは括弧内に「結果・試作・検証・条件・場合・保証・異なる・限る・対象・時点・参考」などがあるものと、括弧外の `※` から行末までを候補とする。複数・位置違反は×。その他の括弧、`※` の内容、結果・数字との対応は△。入れ子・印のない注記・条件の言い換えなどは取りこぼす。
- 結果の不足候補は「結果・実績」または数字＋「件・人・分・秒・%・倍」で検出。件数以外の数字、漢数字、製品名などは人が判断する。
- 件数は出力した検出項目の一致数。同じ投稿に複数件出る。書き出しの重なりは該当する投稿ごと・型ごとに1件ずつ数える。品質の点数ではない。

## 仕様と根拠

文字数の根拠は [X公式のCounting Characters](https://docs.x.com/fundamentals/counting-characters) と [twitter-textのv3設定](https://github.com/twitter/twitter-text/blob/master/config/v3.json)。参照日は2026-11-12。URLは23、通常上限は280、NFC正規化、Unicode範囲による重みを確認した。厳密な絵文字・URL抽出は再実装していない。詳細は [README](../README.md#数え方と制約) を参照。

「外部リンクを付けると届きにくい」「似た投稿はおすすめに載らない」といった配信上の効果は、このスキルでは根拠にしない。編集方針とプラットフォームの公式仕様を混同しない。

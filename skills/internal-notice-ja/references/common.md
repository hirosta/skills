# 共通の決まり

| 項目 | 決まり | 理由 |
| --- | --- | --- |
| 件名 | `【お知らせ】` `【ご依頼】` `【報告】` `【回答】` などの区分＋用件＋日付・期限にする。「〜について」だけで終えない。報告は対象期間・確認時点、回答は回答日でもよい。 | 開く前に用件と時間軸を判断できるようにするため。 |
| 冒頭 | 件名を除く最初の3行に結論・依頼・期限を置く。挨拶は1行まで。依頼がなければ返信不要・対応不要とし、報告では期限の代わりに確認時点を示す。 | 背景説明の後まで読む人の行動が分からない状態を避けるため。 |
| 対象 | 対象者を先に書き、対象外があれば明記する。「各位」だけで対象を済ませない。 | 全社員に送っても全社員の作業とは限らないため。 |
| 敬語 | 下の段階を使い分け、です・ます調を基本にする。「お読みになられる」など二重敬語や、依頼を隠す長い前置きを避ける。 | 読み手への敬意と行動の明確さを両立するため。 |
| 転送 | 部署外・取引先へ渡る前提で略称を解き、社外秘情報、個人の評価・健康情報、未確定の人事は載せない。内部限定の用件であることを示す必要があれば件名と冒頭に「社外秘」と書き、共有範囲を確認する。表示を付けても機微情報を載せてよいことにはならない。 | 転送先では背景や共有範囲が失われやすく、表示だけでは転送を防げないため。 |
| 日時 | 年月日と曜日、24時間表記を使う。同じ文内でも各日付に曜日を付ける。年を省くなら読み手と年が共有されているか確認する。「今週中」「なるべく早く」「近日中」「後ほど」「明日」などで期限を済ませない。 | 読む日や転送日による解釈の違いを避けるため。 |
| 表現 | 絵文字や「みんなで盛り上げましょう！」のような用件と関係のない明るい呼びかけを入れない。箇条書きの数を何でも3つにそろえない。 | 用件より装飾や型が目立つのを避け、必要な情報の数に合わせるため。 |
| 効果 | 「必ず効率が上がります」など測っていない効果を約束しない。目的と確認済みの結果を分ける。 | 期待と事実が混ざるのを避けるため。 |
| 未確定事項 | `［要確認：項目］` と残し、規程名や担当者を補作しない。原因の仮説は事実と分ける。法令判断は担当部署に確認する。 | 読みやすく直す過程で、根拠のない情報が事実になるのを防ぐため。 |

## 敬語の段階

- 全社：所属を問わず分かる語で「対象の方は登録してください」。冒頭の挨拶は省略してもよい。
- 部署内：通常のです・ます調で「担当の方は入力してください」。内輪の略語は部署外に渡るなら説明する。
- 上長：判断や承認の依頼を具体的に「代替案の承認をお願いします」。必要な敬意は保ち、過度に婉曲にしない。
- 社外への転送を想定：正式名称と必要な背景を添え、「ご確認をお願いします」などに整える。社内だけに通じる評価や経緯は外す。社外向けの送付文そのものや法的判断が必要なら、担当部署に確認する。

## 人が読む点検

件名・冒頭・本文で対象と期限が一致しているか、曜日と日付が合うか、数字が同じ条件で比較できるかを読む。敬語の適否、転送で困る情報、規程の根拠、依頼の強さ、文脈で決まる期限はスクリプトで確定できない。要確認が残る文案は送信可能な完成稿として扱わない。

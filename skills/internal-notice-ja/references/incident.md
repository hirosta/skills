# 障害・事故の報告

共通の決まりに加え、以下を使う。

## 型（見出しの順番）

第一報／続報の区分と確認時点 → 影響・依頼 → 次報時刻 → 確認済み → 未確認 → 問い合わせ先。続報では前報からの変更点を確認済みの先頭に置く。

## 書く量の目安

第一報は本文6〜10行程度。続報は変化、継続する影響、次報を中心に5〜12行程度。事故でも個人の健康や評価を載せず、必要な詳細の経路は担当部署に確認する。量のために材料を削ったり、情報を足したりしない。

## 架空の例

会社、部署、規程、数字、日時、出来事はすべて架空。

```text
件名：【報告】【社外秘】会議室予約の登録不可・第一報・2026年11月5日（木）10:15時点
社外秘：関係する予約担当者・上長向け。2026年11月5日（木）10:00から会議室予約システムに登録できません。
復旧連絡まで新規登録を控えてください。返信不要です。
次の報告は2026年11月5日（木）11:00に行います。変化がなくても報告します。

確認済み：2026年11月5日（木）10:15時点で、予約担当者8人から登録不可の申告があります。
未確認：全体の影響範囲、原因、復旧見込みは不明です。
問い合わせ先：情報システム窓口。社外転送はしないでください。
```

## 続報の組み立て

同じ架空事例の続報では、確認時点を更新し、第一報の推測を事実に変えない。次は、追加の架空の材料「11:00にも登録不可を確認、調査中で原因・復旧見込みは不明、次報12:00」がある場合の続報例。

```text
件名：【報告】【社外秘】会議室予約の登録不可・続報・2026年11月5日（木）11:00時点
社外秘：関係する予約担当者・上長向け。2026年11月5日（木）11:00時点でも登録できません。
復旧連絡まで新規登録を控えてください。返信不要です。
次の報告は2026年11月5日（木）12:00に行います。変化がなくても報告します。

前報からの変更点：登録不可が続いていることを確認しました。調査を継続しています。
確認済み：2026年11月5日（木）10:15時点の申告人数は8人です。全体の影響人数ではありません。
未確認：全体の影響範囲、原因、復旧見込みは引き続き不明です。
問い合わせ先：情報システム窓口。社外転送はしないでください。
```

## よくある失敗

申告8人を全影響8人と書く。原因の推測を断定する。復旧見込みが不明なのに時刻を作る。変化なしで次報を省く。

# ai-smell-ja

日本語の文章にある決まり文句、同じ文型の繰り返し、過剰な前置きなどを見つけ、意味を保って書き直すスキルです。業務連絡、ブログ、提案文などを対象にします。修正文と、変更箇所・理由を返します。

「AIっぽさ」は点検の観点です。人間の文章にも同じ表現は現れます。AIによる執筆の判定、検出器の回避、文章の品質向上を保証するものではありません。

## 入れ方

### CLIで入れる

Node.js 22.20以上とnpxが使える環境で、導入先のプロジェクトから次を実行します。対話画面で利用するAIエージェントと導入先を確認してください。

```bash
npx skills add hirosta/skills --skill ai-smell-ja
```

リポジトリのスキルをまとめて入れる場合は、`npx skills add hirosta/skills` を実行し、対話画面ですべてのスキルを選びます。

CLIには匿名の利用集計（テレメトリー）があり、環境変数 `DISABLE_TELEMETRY=1` で無効にできます。たとえば、`DISABLE_TELEMETRY=1 npx skills add hirosta/skills --skill ai-smell-ja` と実行します。詳しくは[公式ドキュメント](https://www.skills.sh/docs)と[FAQ](https://www.skills.sh/docs/faq)を参照してください。

### 手でコピーする

このリポジトリを取得したフォルダーで、次を実行します。同名のフォルダーがある場合は内容を確認し、上書きするか決めてからコピーしてください。

```bash
mkdir -p ~/.claude/skills/
cp -r skills/ai-smell-ja ~/.claude/skills/
```

Pythonの補助スクリプトはPython 3の標準ライブラリだけで動き、追加の依存は不要です。スキル自体の利用には、スキルを読み込めるAIエージェントが必要です。

## 使い方

スキルを読み込んだエージェントに、対象の文章を添えて依頼します。

```text
ai-smell-jaで、次の業務連絡のAIっぽい表現を見直してください。
意味、数字、期限、依頼の強さは変えず、修正文と変更理由を出してください。
（ここに対象の文章を貼る）
```

機械的な点検だけを実行する場合は、リポジトリのルートから次を実行します。

```bash
python3 skills/ai-smell-ja/scripts/check.py skills/ai-smell-ja/examples/notice-before.txt
python3 skills/ai-smell-ja/scripts/check.py skills/ai-smell-ja/examples/notice-after.txt
```

各一致を `行番号:列番号`、分類名、一致文字列の順にタブ区切りで出し、分類別件数と合計を表示します。行と列は1から始まります。入力はUTF-8（BOM付きも可）です。検出の有無にかかわらず正常終了は0、入力を読めない場合や引数の誤りは2です。文章や設定の変更、ネットワークへのアクセスはしません。出力には原文の一致文字列を含むため、公開先に貼る場合は内容を確認してください。

検出対象と数え方は [references/patterns-ja.md](references/patterns-ja.md) にあります。検出箇所は修正候補であり、使用禁止語ではありません。カタカナ語、文型の繰り返し、段落構成などは文章を読んで判断します。

## 試した結果

条件は、GPT-6（Codex）がこのスキルの手順に沿って作成・書き直しした架空の短文3本です。業務連絡、ブログ、提案文を各1本用意し、書き直し前後の計6ファイルに同じ `check.py` を実行しました。実在の人物や業務の記録ではありません。独立したモデルや読み手による評価は行っていません。

| 種類 | 書き直し前 | 書き直し後 | 検出件数（前 → 後） |
| --- | --- | --- | --- |
| 業務連絡 | [notice-before.txt](examples/notice-before.txt) | [notice-after.txt](examples/notice-after.txt) | 3 → 1 |
| ブログ | [blog-before.txt](examples/blog-before.txt) | [blog-after.txt](examples/blog-after.txt) | 3 → 0 |
| 提案文 | [proposal-before.txt](examples/proposal-before.txt) | [proposal-after.txt](examples/proposal-after.txt) | 2 → 0 |
| 合計 | 3本 | 3本 | 8 → 1 |

### 文ごとの照合

行番号は各例文の文に対応します。作成・書き直しを担当した同じAIが全文を読み比べ、次の点を確認しました。

| 素材・原文の行 | 修正文の行 | 変更と保持した内容 |
| --- | --- | --- |
| 業務連絡1 | 1 | 「において」を解き、期限を守る重要性を「大切です」で維持。提出義務を新たに加えていない。 |
| 業務連絡2 | 2 | 語順を変更。形式の多様さを残すため「さまざまな」は維持。形式名や件数は加えていない。 |
| 業務連絡3 | 3 | 変更なし。「研修日の3日前」「午後5時」を保持。具体的な日付は推測していない。 |
| 業務連絡4 | 4 | 変更なし。提出先の研修担当を保持。 |
| ブログ1 | 1 | 前置きを省き、「における」を「での」に変更。架空の読書会の記録方法を紹介する趣旨は保持。 |
| ブログ2 | 2 | 「一つ目の工夫は」の型を解く。「感想」「1人2行」を保持。 |
| ブログ3 | 3 | 同じ型の繰り返しを解く。共有時期は会の終了後、共有範囲は参加者だけのまま。 |
| ブログ4 | 対応文なし | 定型の呼びかけを削除。この記事では回答を収集する手順や依頼はなく、事実・数字の削除はない。読者への呼びかけの語調は変わる。 |
| 提案文1 | 1 | 「において」「を実現」を言い換え。対象は架空の備品貸出窓口、目的は記入漏れの削減、提案の段階のまま。 |
| 提案文2 | 2 | 導入を短くした。「6項目から4項目」、用紙の記入欄を減らす案であることを保持。実施済みとはしていない。 |
| 提案文3 | 3 | 接続語を省略。「7日間のまま」「延長はできない」を保持。 |
| 提案文4 | 4 | 「試行前」を「まだ試していない」に変更。未試行と、効果が分からないという留保を保持。 |

### 分かったこと

- この3本では、実装した文字列の検出件数が合計8件から1件になりました。業務連絡の「さまざまな」は意味を保つため残しました。0件にすることは目標にしていません。
- 上の照合では、期限、数値、対象、否定、提案段階と未確認の効果を保持できました。呼びかけの削除を含む語調の変更は表に明記しました。
- 文型の繰り返しを直したブログの2・3行目は、機械検出では前後とも0件です。件数だけではその変更を表せません。

### まだ分からないこと・注意点

- 短い架空の素材3本だけの結果です。長文、会話、論文、契約書などに同じように適するかは未確認です。とくに定型や厳密な用語が必要な文章では、表現を残す判断が必要です。
- 辞書にない表記や活用、過剰さ、カタカナ語の適否、強調の根拠は機械では判定しません。必要な表現も拾い、問題のある表現を見逃すこともあります。
- 自然さ、読みやすさ、作業時間は測っていません。意味の保持も同じAIによる照合であり、第三者による保証ではありません。
- 利用時は修正文の情報と語調を確認してください。ファイルへの保存は内容と対象を確認してから行う手順です。

# dads-page-check

デジタル庁デザインシステムを参考にした非公式のスキルで、デジタル庁とは関係がない。

Webページの文字、色、リンク、キーボード操作、フォームなどを点検し、現状・修正案・優先度を返します。中小企業や団体のサイトでも、読みやすさと使いやすさの基本を見直すときに使えます。DADS β版やWCAGへの適合を認証・保証するものではありません。

## 入れ方

このリポジトリを取得したフォルダーで、次を実行します。同名のスキルがある場合は、内容を確認し、上書きするか決めてからコピーしてください。

```bash
mkdir -p ~/.claude/skills/
cp -r skills/dads-page-check ~/.claude/skills/
```

スキルを読み込めるAIエージェントが必要です。補助スクリプトはPython 3.9以上の標準ライブラリだけで動き、追加の依存は不要です。

## 使い方

スキルを読み込んだエージェントに、対象と範囲を添えて依頼します。

```text
dads-page-checkで、添付のHTMLとCSSのフォームを点検してください。
問題と未確認項目を分け、修正文案とCSS・HTMLの差分案を出してください。
ファイルはまだ書き換えないでください。
```

URLでも指定できます。URLの閲覧は対象サイトや埋込リソースへのアクセスを伴うため、利用者の確認後に行う手順です。送信・購入・投稿・予約等の操作は行いません。ファイルや設定の変更は、修正内容を確認した利用者が依頼した場合だけ行います。

静的点検だけなら、リポジトリのルートで実行します。

```bash
python3 skills/dads-page-check/scripts/check.py skills/dads-page-check/examples/before.html --css skills/dads-page-check/examples/before.css
python3 skills/dads-page-check/scripts/check.py skills/dads-page-check/examples/after.html --css skills/dads-page-check/examples/after.css
python3 skills/dads-page-check/scripts/check.py --contrast '#3B3538' '#F6F3EE'
python3 skills/dads-page-check/scripts/check.py --contrast '#D1D5DB' '#FFFFFF'
```

入力はUTF-8（BOM付きも可）。`--css` は繰り返せます。HTML内のstyle要素とstyle属性も対象です。スクリプトはファイルの読み取りと結果出力だけを行い、ファイル・設定を書き換えず、ネットワークに接続しません。HTMLのlinkやCSSの@importを自動で読み込むこともありません。

出力は `行番号:種類:ファイル名:内容`、分類別件数、合計、注意書きです。行番号は1から始まり、CSSは宣言の行、style属性は要素の開始行を指します。内容にはセレクターや指定値が含まれるため、外部へ共有する前に確認してください。候補の有無にかかわらず正常終了は0、引数・読取・色指定のエラーは2です。エラーは標準エラー出力に表示します。

`--contrast` はファイル指定と併用せず、不透明な2色だけを計算します。#RGB、#RRGGBB、整数のrgb(r, g, b)、black、whiteに対応します。未対応の色を白や黒と推定せずエラーにします。

## 点検する基準

詳細、例外、静的点検の対応範囲は [references/criteria.md](references/criteria.md) にあります。各項目の参照日は2026-10-21、実装時に公式ページを再確認した日は2026-10-22です。公式の文章・サンプルコードは転載せず、自分の言葉で整理しています。

| 項目 | 基準の概要 | 公式の参照ページ |
| --- | --- | --- |
| 文字・行高・書体 | 本文・UIは原則16px以上、14pxは制約時のみ、14px未満は原則避ける。本文行高1.5以上。日本語斜体は必要な理由がなければ避ける。 | [タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/) |
| 色・フォーカス | 文字4.5:1以上、必要な枠線・アイコン・フォーカス表示は隣接色と3:1以上。Tab移動の位置を可視化する。 | [カラー](https://design.digital.go.jp/dads/foundations/color/)・[アクセシビリティ](https://design.digital.go.jp/dads/foundations/color/accessibility/) |
| リンク | 本文の下線を基本に色以外でも区別。新規タブの予告、ファイル形式・容量、ホバー時のサイズ変化を確認する。 | [リンクテキスト](https://design.digital.go.jp/dads/foundations/link-text/) |
| 押せる領域 | ボタン44×44px以上。リンクは44×44pxが望ましく、24×24pxの目安と間隔・例外を確認。 | [ボタンの使い方](https://design.digital.go.jp/dads/components/button/usage/)・[ボタンのアクセシビリティ](https://design.digital.go.jp/dads/components/button/accessibility/)・[リンクのアクセシビリティ](https://design.digital.go.jp/dads/foundations/link-text/accessibility/) |
| ボタンの階層 | 塗り・枠・文字等で役割を示す。主ボタンは原則1画面1つ。無効化が必要なら操作可能になる条件を説明する。 | [ボタンの使い方](https://design.digital.go.jp/dads/components/button/usage/) |
| フォーム | ラベル・条件・入力欄・エラーの関連と順序、要否、原因と訂正方法を示す文を確認。placeholderを説明の代わりにしない。 | [インプットテキストの使い方](https://design.digital.go.jp/dads/components/input-text/usage/) |
| 余白・角丸 | 8px基準・3〜5段階の余白は設計例。角丸は部品ごとに規則を持たせ、ばらつきを確認する。 | [余白](https://design.digital.go.jp/dads/foundations/spacing/)・[角の形状](https://design.digital.go.jp/dads/foundations/corner-shapes/) |

要件の簡略な目安と公式の記述に差がある箇所は、公式の留保を残しました。フォームは横並びも許容され、日本語斜体は必要な理由がある場合の例外があります。ホバー時の文字サイズ変更も他要素に影響しない場合の留保があります。余白8pxは絶対条件ではありません。これらは一律の違反とは扱いません。

### 色の計算の照合

スクリプトとは別に、Python標準ライブラリのDecimal（精度40桁）で [WCAG 2.2の相対輝度の式](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance) を当てはめて照合しました。各成分の線形化、重み付きの合計、比の計算を分け、表示の小数6桁まで一致することを確認しました。式は [基準一覧](references/criteria.md) にあります。

| 前景 / 背景 | 相対輝度（前景 / 背景、概数） | 比（小数6桁） | 4.5:1 / 3:1 |
| --- | --- | ---: | --- |
| #3B3538 / #F6F3EE | 0.037615366 / 0.898670610 | 10.827674 | 両方満たす |
| #D1D5DB / #FFFFFF | 0.662582822 / 1 | 1.473513 | 両方届かない |
| #000 / #fff | 0 / 1 | 21.000000 | 両方満たす |
| rgb(255, 255, 255) / white | 1 / 1 | 1.000000 | 両方届かない |

例：最初の組は `(0.898670610 + 0.05) / (0.037615366 + 0.05)`。実際の計算には丸める前の輝度を使い、判定も丸める前の比で行います。

### 分かったこと

- この素材では、文字サイズ・行高・下線・フォーカス削除・ラベル不足・説明の関連付け不足・日本語斜体・同一規則の色比の候補を出せました。修正後の同じ点検では候補0件でした。
- 別の架空の境界例1ページを `<一時領域>` で手動実行し、見出しの行高1.4と14px指定は検出せず、.8remと13px、style属性の12pxを拾うことを確認しました。for/idと内包ラベル、aria-describedbyの説明、hidden・submit入力の除外も確認しました。
- 同じCSS対象のfocus-visibleによる代替、同じ要素・同じ条件のfocus系ring幅指定がある場合はフォーカス削除候補を出さず、別対象や異なる幅条件の代替では候補を残しました。@media内、style要素、引用符内の波括弧、未解決の色変数も手動例で確認しました。
- 色の数式は上の4組で照合しました。ブラウザの描画結果との比較ではありません。

### フォーカス判定の修正確認

上記と同じモデルで、`<一時領域>` に架空のリンクを含むHTMLを16件用意し、1件ずつ手動実行しました。いずれもoutlineの削除指定を含みます。色コードやrgb関数の数字を幅・影の寸法と混同しないように修正し、次を確認しました。自動テストは追加していません。

| 指定・条件 | 素材数 | フォーカス候補数（各素材） |
| --- | ---: | ---: |
| `box-shadow:0 0 0 #123456`、または寸法がすべて0のrgb色の影 | 2 | 1 |
| 同じ対象のfocus-visibleに `outline:2px solid rgb(0,0,0)` | 1 | 0 |
| 幅が0px・0.0remのoutline | 2 | 1 |
| 正の広がり・負のオフセット・正のぼかしがある影 | 3 | 0 |
| transparent色の影・outline | 2 | 1 |
| 別対象、または別の@media条件のoutline | 2 | 1 |
| ゼロ寸法の影と、正の広がりがある影の併記 | 1 | 0 |
| オフセットとぼかしが0で、広がりが負の影 | 1 | 1 |
| 幅が未解決の変数のoutline | 1 | 1 |
| 幅を省略した `outline:solid rgb(0,0,0)` | 1 | 0 |

同梱例の分類別件数も再確認し、上の表の20件→0件と一致しました。代替表示の存在を推定する確認であり、色の差や実表示の見え方を検証したものではありません。

### まだ分からないこと・注意点

- 静的点検はCSSの継承や詳細度、JavaScript、計算後の表示、ルート文字サイズ、背景画像や透過を解決しません。Tailwind風のクラスは標準値の仮定で、独自設定は未確認です。CSSの完全な構文解析器ではありません。
- CSSの代替フォーカス表示は寸法と色を分けて推定します。色は上記の不透明色のみ対応し、未対応の色・変数・透過を含む指定は代替と認識しません。outlineの個別プロパティや宣言の上書き、異なる単位の影の相殺も解決しないため、候補を読み直してください。
- 14〜15pxの本文、押せる範囲、枠線の比、必須・任意やエラー文の妥当性、余白・角丸の一貫性は、コードを読むかブラウザで別途確認します。ラベルの視覚的な非表示も機械では判断しません。
- この実装の検証ではブラウザでの画面確認は行っていません。計算後の文字・行高・色、Tab移動、ターゲット領域、375px・390px表示は未確認です。フォームのエラーは静的な見本で、動的な入力検証や送信処理はありません。
- 読みやすさ、操作性、作業時間は測っていません。1ページの候補数から一般的な効果やDADS・WCAGへの適合を保証できません。利用者のサイトでは未検出・誤検出の双方があり得ます。
